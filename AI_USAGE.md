# Как применялся ИИ

## Исходная задача

Пользователь передал техническое задание лабораторной работы о генераторе экзаменационных билетов и попросил выполнить его на Go для другого учебного предмета. Отдельно он попросил создать репозиторий GitHub и сделать применение нейросетей видимым в нём.

## Что сделано с помощью OpenAI Codex

1. Извлечены и разобраны требования DOCX: ввод студента, номер билета 1–20, файл `journal.xlsx`, сохранение после каждой записи, ESC, повтор пустого ввода и ошибка при занятом файле.
2. Спроектирована и написана консольная программа на Go. Для генерации номера используется `crypto/rand`; XLSX создаётся средствами стандартной библиотеки Go.
3. По уточнению пользователя добавлены 20 оригинальных вопросов на румынском по предмету Proiectarea Sistemelor Informaționale. Темы сверены с [содержанием учебного материала UTM](https://repository.utm.md/handle/5014/15231); вопросы не копируют официальный экзаменационный набор.
4. Добавлены тесты по основным сценариям из ТЗ и проверка GitHub Actions.
5. Подготовлены README и это описание, чтобы было видно, где именно применялся ИИ.

## Принятые решения

- Номер может повторяться у разных студентов: ТЗ требует диапазон 1–20 и не требует уникальности.
- Предмет задан в программе, а структура Excel сохраняет четыре столбца из ТЗ.
- Вопросы закреплены за номерами 1–20 в исходном коде. В Excel хранится номер, поэтому вопрос можно восстановить по опубликованному банку.
- Журнал студентов исключён из Git, поскольку имена учащихся не нужны в общедоступном репозитории.
- При ошибке сохранения программа удерживает введённые данные и повторяет запись после Enter.

## Проверка и ограничения

Локально на Go 1.27.3 прошли `go test ./...` и `go vet ./...`. Приложение проверено с тремя студентами в первом запуске и двумя во втором; `openpyxl` прочитал XLSX с заголовком и пятью строками. После добавления стандартного стиля новый XLSX открылся в `openpyxl` без предупреждений. Отдельно после сохранения одной записи процесс был принудительно завершён, затем файл открыт повторно — запись сохранилась. В терминале проверено завершение по ESC без Enter.

После запроса о запуске на ноутбуке с Windows ввод переключён на официальный пакет `golang.org/x/term`, который управляет консолью на Windows, macOS и Linux. Добавлена сборка Windows `.exe` и тесты на Windows в GitHub Actions. Готовый архив распространяется через GitHub Releases, поэтому устанавливать Go для использования программы не требуется.

## Лабораторная работа 2

Пользователь передал новое ТЗ на графический интерфейс и уточнил, что нужны демонстрационные входные файлы, выбор подходящей GUI-библиотеки и открытая история разработки с Codex. Упомянутый в ТЗ Copilot Chat не использовался; пользователь подтвердил, что история работы с Codex подходит.

OpenAI Codex разобрал требования, спроектировал отдельную ветку `lab2-ui-tickets`, написал GUI на Fyne и слой чтения/записи файлов, подготовил демонстрационные `students.xlsx` и `tickets.docx`, добавил тесты и Windows-сборку в GitHub Actions. Вымышленные студенты и учебные вопросы обозначены в README. История коммитов, эта запись и результаты CI показывают конкретные шаги применения ИИ.

Принятое решение для повтора: ключом служат группа, фамилия и имя; номер берётся из самой ранней строки `results.xlsx`. При ошибке сохранения повторная попытка не меняет выбранный номер. Для нового студента выбор идёт только среди корректно прочитанных билетов. Лаб 1 оставлена доступной как консольная программа.

Локально прошли `go test ./...` и `go vet ./...`; демонстрационные XLSX и DOCX открыты и визуально проверены. GitHub Actions прошёл Linux-тесты и анализ, тесты ядра на Windows и сборку Windows GUI. Скачанный артефакт проверен как Windows x64 GUI-файл с обоими входными файлами и опубликован в релизе `lab2-v1.0.0`. Интерактивный запуск на физическом Windows-компьютере не выполнялся.
